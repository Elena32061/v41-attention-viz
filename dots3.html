来源与限定

维度来源

model_dots3.js 里 CFG 的每一项都抄自 dots3 checkpoint 的 config.json，字段名原样保留。 QKV_A 1728 = 1024 + 512 + 64 + 128（gate 列 = 本卡头数，headwise，对齐到 8）、 Q_B 24576 = 128×(128+64)、W_KC/W_VC 每头 128×512 / 512×128、 O 的 K = 128×128 这些换算，以及哪一维被 TP 切、decode 为什么不跑 kv_b 的 GEMM， 来自实现源码 dots3_common/modeling.py。

稀疏方式

full 层用 DSA indexer（index_n_heads=64、index_head_dim=128） 对整段上下文打分，选 index_topk=2048 个 token；没有 V4.1 的 候选块那一级，所以 indexer 的打分量随上下文线性增长、没有封顶。 SWA 层只看最近 sliding_window_size − 1 = 511 个 token，不用 indexer。

这里没有的东西

  • 没有任何实测时间、吞吐或 TPOT。块数和轮数是理想排布的算术结果， 不含 L2、尾效应、graph padding 和 kernel 本身的 tile 形状差异。
  • W_KC / W_VC 实际 kernel 的 tile 不是 128×128，这里按统一口径算，只用于比较量级。
  • 只画 decode 的吸收路径。prefill 走展开的 MHA（kv_b 作为 GEMM 跑在上下文上），没有画。
  • 只画 attention。MoE（256 选 8 + 1 共享）、dense 第 0 层、gate 的逐元素乘都没有画。
  • checkpoint 是 BF16，没有 quantization_config；如果部署时转 FP8，权重字节减半，形状不变。
  • 轮数假设每个块代价相同，实际不是 —— K 不同的投影每块的活差很多。
